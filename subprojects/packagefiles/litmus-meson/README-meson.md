# litmus meson subproject

[litmus](https://github.com/notroj/litmus) is Joe Orton's WebDAV server
protocol compliance test suite.  It is no longer packaged by all
distributions (Fedora retired it after F38), so this subproject builds
it from source when no `litmus` program is installed on the system.

`litmus.wrap` checks out the litmus git tree and this directory is
applied over it as a patch directory (`patch_directory`), adding:

- `meson.build`: build definition for all the test programs of
  litmus' own build (the default suites `basic`, `http`, `props`,
  `locks`, `copymove`, plus `largefile`, `protected` and the
  `lockbomb` stress test) and the `litmus(1)` driver script, which
  runs the default suites.  The non-default programs can be run with
  the `TESTS` environment variable, e.g. `TESTS=largefile litmus URL`.
  The build needs the [neon](https://notroj.github.io/neon/)
  HTTP/WebDAV client library (neon-devel) installed on the system.
- `config.h.in`: template for the configuration header, standing in
  for the one generated by litmus' configure script (neon version
  macros, printf format strings, feature checks).
- `litmus.sh.in`: template for the driver script, modelled after
  litmus' own `litmus.in`.
- `neon-test-common/`: a vendored copy of neon's test framework
  (`tests.c`, `tests.h`, `child.h`), taken from the exact neon commit
  pinned by litmus 0.18 as a git submodule
  (notroj/neon@170c36704bfc2ac8b0e5607c3e1fdd4c159674db).  In the
  litmus tree this code is reachable via the `test-common` symlink
  into the `neon` submodule; vendoring the three files needed by
  litmus avoids having to clone neon too.  Keep these files in sync
  with the submodule commit when bumping the litmus revision in
  `litmus.wrap`.

When bumping the litmus revision, also update the version in the
`project()` call of `meson.build`, the source list of test suites if
upstream changed them (`TESTS` in litmus' `configure.ac`), and
refresh the vendored `neon-test-common/` files from the new submodule
commit.
